A node is a computer with a strong NVIDIA GPU that serves the model to AIs@home users. It
runs two services: `llama-server` (the model, on `127.0.0.1` only) and `aisathome-node`, a
small agent that connects **outward** to the gateway and passes requests through.

Running a node is **voluntary and unpaid**. There is no token and no payment. Your node
earns [credit](/node/credit/) in BOINC's unit: recognition, not money.

## What you need

- An NVIDIA GPU with **16 GB or more**. The context depends on the card
  ([model settings](/node/presets/)):
  - **16 GB** (RTX 4080, 5070 Ti, 5080 class): 80k context with the 3-bit model file
    (`UD-Q3_K_XL`), and at most a **light desktop** on that card: about 1.5 GB of GPU memory
    for the screen and other programs. A heavier desktop needs the screen on the
    motherboard's graphics;
  - **24 GB and more** (RTX 3090, 4090, 5090 class): 192k context with the 4-bit file
    (`UD-IQ4_XS`).
- A card fast enough on long prompts: the installer measures it and needs at least
  20 tokens/s after a 32,000-token prompt (slower 16 GB cards such as the RTX 4060 Ti and
  5060 Ti do not pass).
- **Linux:** x86_64 with systemd and glibc 2.35 or newer (Ubuntu 22.04, Debian 12 or newer), and
  NVIDIA driver {needs.linuxDriver} or newer ({needs.linuxDriverRTX50} for an RTX 50).
  **Windows:** 10 or 11, 64-bit, and NVIDIA driver {needs.windowsDriver} or newer
  ({needs.windowsDriverRTX50} for an RTX 50). In both, `nvidia-smi` must work.
- About {needs.diskGB} GB of disk for the model. With the prebuilt bundle, the install is mostly the
  {needs.modelGB} GB download; building llama.cpp yourself takes about an hour.
- **You must be 18 or older.** Running a node means you accept the [terms](/about/terms/)
  (for a linked node, the [operator terms, §6](/about/terms/#6-requests-your-node-answers)). The
  installers ask you to confirm both before the node starts.
- An **account** is optional: sign in on [your account page](/account) with GitHub or Google. A node
  links to it in your browser (below); up to 10 nodes per account, at most 10 of them connected
  from one internet address. The network takes 25 nodes for now; when it is full, the approval
  page says so. Without an account, a node does science only ([below](#without-an-account-science-only)).

## Three steps

1. **Install.** On Windows (new in v0.5.0), one installer sets up the node as a service with a
   tray icon, and the node's local page walks through the card check, the model download and a
   speed test: see [Install on Windows](/node/windows/). On Linux, the
   [prebuilt bundle](/node/install/) installs it with one command.
2. **Link it to your account.** At the end, the node shows a link and a code: on Windows the
   **Link to my account** button opens it in your browser; on Linux the installer prints it (and
   `sudo aisathome-node link` does it again later). Open the link in your browser, sign in, check that the page shows the same code and approve.
   Approving creates the node on your account, and running it means you accept the
   [operator terms (§6)](/about/terms/#6-requests-your-node-answers): then your node answers
   people's chats as well as science. **Science only on my nodes** on the account page turns
   chats off for all your nodes.
3. **Confirm and check.** The node starts by itself. **Your nodes** on your account page lists it:
   press **This is my machine** on it. Until you do, it is not one of your own nodes and gets none
   of your personal data. On Linux, `aisathome-node status` says `CONNECTED`.

Only approve a code that a machine of yours shows you. A code someone sends you would add
*their* machine to your account; that is why a linked node gets your personal data only after you
confirm it.

**Advanced: a node token.** You can also create a node on your account page with **Add a node**
and paste its token: on the Windows setup page under **Advanced: paste a node token**, or at the
Linux installer's token question (or piped in for scripts: `cat token.txt | sudo ./install.sh`).
A node run by hand reads it from its config or the `AISATHOME_NODE_TOKEN` environment variable.

## How the node runs

- **No open ports.** The node only dials out; nothing listens on your network.
- **Sandboxed.** Both services run as the unprivileged user `aisathome`: no access to
  `/home`, a read-only system, no new privileges.
- **Fewer traces on disk.** No core dumps, no swap for the services, a bounded prompt cache
  in RAM, no prompt logging.
- **Anonymous requests.** Your node never learns who sent a request.
- **Stop any time:** see below.

## Stop, remove, link later

**The node's own page.** Once installed, the node has a page on your computer at
**http://127.0.0.1:7381/** (Windows opens it; on Linux the installer prints the address, and
desktops get an "AIs@home node" menu entry). It shows the node's status, its GPU and what it
served, and has **Pause** and **Restart engine** behind a local password
(`sudo cat /etc/aisathome-node/ui-password` on Linux); on Windows also **Stop engine** and the
setup page. Details: [Day to day](/node/operate/#local-ui).

| | Linux | Windows |
|---|---|---|
| Pause (the model stays loaded) | **Pause** on the node's page | **Pause** on the node's page |
| Stop and free the GPU | `sudo systemctl stop aisathome-node aisathome-llama` | **Stop engine** in the tray menu or on the node's page |
| Start again | `sudo systemctl start aisathome-llama aisathome-node` | **Start engine** |
| Link to an account | `sudo aisathome-node link` (credit starts then) | **Link to my account** on the setup page |
| Uninstall | `sudo ./uninstall.sh` in the unpacked bundle (below) | Settings → Apps → **AIs@home node** → Uninstall |

**Uninstall on Linux.** `uninstall.sh` comes with the bundle: run `sudo ./uninstall.sh` in the
folder you installed from. It removes the services, the program and its settings and keeps the
model; `sudo ./uninstall.sh --purge` removes the model and the `aisathome` user too. The one-line
start unpacks the bundle in a temporary folder (it prints where, under `/tmp`), which a restart

## How new nodes start

- A new node serves requests from day one. Requests with tools (agents such as opencode)
  reach it only from users who allow volunteer nodes for agents.
- Answers are not stopped for looking dangerous: if one looks like it injects a dangerous
  command, the gateway logs it with a short excerpt for us to look at. The people who run
  agents approve each command themselves. A node can still be **held** (for example when it
  fails the model check); the account page shows that.
- No single volunteer gets more than about a third of the conversations while others are free.
- Your node earns [credit](/node/credit/), except for requests you send yourself.

## What you are responsible for

- Your machine, its power bill and its other GPU work (BOINC, games). The node uses the GPU
  fully while it serves.
- **Not looking at what you serve:** don’t log, store, copy or inspect prompts or answers,
  and don’t tamper with them. This is a promise to users; see the
  [terms](/about/terms/).
- Keeping your node token secret (the node keeps it in a file only administrators can read), and
  telling us if it leaks.
